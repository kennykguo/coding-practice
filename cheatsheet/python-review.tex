\section{Find the next useful step}\label{sec:reason}
\begin{enumerate}
\item State what counts as a valid answer. Check order, duplicates, reuse, and whether you must change the input.
\item Describe a direct solution. Find the search, repeated calculation, or repeated state that makes it expensive.
\item Choose the smallest summary that removes that work. State exactly what each variable or table entry means.
\item Explain why an update preserves that meaning. Then write the loop and test a small case.
\end{enumerate}
For a pair with a target sum, a direct solution searches for a partner for each value.
Once \cd{x} is fixed, the partner is exactly \cd{target - x}. A dictionary can answer that question.
If the output changes from indexes to a count of pairs, store counts instead of indexes.
The reusable idea is the question the dictionary answers.

\begin{longtable}{@{}L{5.5cm}L{10.5cm}@{}}
\toprule Repeated work & Idea to test \\ \midrule\endhead
Search earlier items for one exact value & Store membership, indexes, or counts (\sect{hash}).\\
Recompute a summary on both sides & Build prefix and suffix information (\sect{prefix}).\\
Try every pair in sorted input & Prove that moving an end discards impossible pairs (\sect{pointers}).\\
Rebuild overlapping contiguous ranges & Add the new item and remove the old item (\sect{window}).\\
Search ahead for the first greater value & Keep unresolved candidates in a stack (\sect{stack}).\\
Try every possible answer & Test whether feasibility changes only once (\sect{search}).\\
Repeatedly select the next smallest item & Keep candidates in a heap (\sect{heap}).\\
Explore choices with the same future & Define the future state, then cache it (\sect{dp}).\\
Find the fewest equal-cost moves & Model states and moves as a graph. Use BFS (\sect{graph}).\\
Decide what can be done next & Track unmet prerequisites (\sect{structure}).\\
\bottomrule
\end{longtable}
\textbf{Use constraints to reject work.} About \(10^5\) items usually calls for a linear or sorting-based solution.
A few thousand can allow a quadratic loop. A choice set near 20 can allow subset search.
These are estimates, not time guarantees. Count states, transitions, copying, and output size.
An explicit logarithmic-time or constant-space requirement is part of the task.

\textbf{Test the assumption when the problem changes.}
Negative numbers can break a sum-based sliding window. Reuse changes a combination search.
Weights change BFS. A move limit adds state. Duplicates change comparison rules.
Keep the technique only if its correctness argument still holds.

\section{Python operations to recall}\label{sec:python}
Examples use Python 3.10+ features and work on Python 3.13. Heap examples use negation for a max-heap.
In a code block, \texttt{\# ->} introduces the expected result.

\subsection{Loops, indexes, and conditions}
Iterate values directly. Use \cd{enumerate} when you also need an index.
\cd{range(start, stop, step)} excludes \cd{stop}. A slice excludes its right end.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-1}{}
\begin{pyex}
nums = [4, 7, 2]
list(enumerate(nums))                 # -> [(0, 4), (1, 7), (2, 2)]
list(range(2, -1, -1))                # -> [2, 1, 0]
nums[1:3], nums[-1], nums[::-1]        # -> ([7, 2], 2, [2, 7, 4])
list(zip([1, 2], [10, 20]))           # -> [(1, 10), (2, 20)]
sum(x * x for x in nums)              # -> 69
all(x > 0 for x in nums)              # -> True
any(x % 2 == 0 for x in nums)         # -> True
[x for x in nums if x > 3]           # -> [4, 7]
[(r, c) for r in range(2) for c in range(2)]
# -> [(0, 0), (0, 1), (1, 0), (1, 1)]
value = 5 if nums else 0
value                                 # -> 5
\end{pyex}
\hypertarget{example-end-1}{}
\end{minipage}\par
Empty containers, zero, \cd{None}, and \cd{False} are false in a condition.
Use \cd{is None} when zero is valid. Use \cd{==} for equal values and \cd{is} for the same object.
\cd{and} and \cd{or} short-circuit and return an operand.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-2}{}
\begin{pyex}
stack = []
bool(stack), bool(0), bool(None)       # -> (False, False, False)
bool(stack and stack[-1] == 3)         # -> False
x = 0
x is None                             # -> False
0 <= x < 3                            # -> True
\end{pyex}
\hypertarget{example-end-2}{}
\end{minipage}\par
In a \cd{while} loop, each path must move a pointer, remove work, or return.
\cd{break} leaves the loop; \cd{continue} starts its next iteration.
Check bounds before indexing. A negative index can silently read the last item.

\subsection{Lists, tuples, and copies}
Use a list for a stack or indexed table. \cd{append} adds one object; \cd{extend} adds its elements.
\cd{pop()} returns the last element. \cd{pop(0)} shifts the remaining list.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-3}{}
\begin{pyex}
a = [1]
a.append([2, 3])
a                                     # -> [1, [2, 3]]
a.extend([4, 5])
a.pop()                               # -> 5
a                                     # -> [1, [2, 3], 4]
r, c = (2, 3)
r, c = c, r                           # read the right side first
(r, c), (4,)                         # -> ((3, 2), (4,))
\end{pyex}
\hypertarget{example-end-3}{}
\end{minipage}\par
Assignment shares an object. A shallow copy copies only the outer list.
For a numeric grid, copy each row. Allocate each row separately.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-4}{}
\begin{pyex}
grid = [[0] * 2 for _ in range(2)]
alias = grid
outer = grid.copy()
copied = [row[:] for row in grid]
grid[0][0] = 7
alias, outer, copied
# -> ([[7, 0], [0, 0]], [[7, 0], [0, 0]], [[0, 0], [0, 0]])
bad = [[0] * 2] * 2
bad[0][0] = 9
bad                                   # -> [[9, 0], [9, 0]]
\end{pyex}
\hypertarget{example-end-4}{}
\end{minipage}\par
Save a backtracking path with \cd{path.copy()}.
Use \cd{copy.deepcopy} if deeper mutable objects also need independent copies.
For node graphs, use an original-to-copy map (\sect{linked}).

\subsection{Dictionaries, sets, and counting}
Dictionary membership tests keys. \cd{get(key, default)} reads without inserting.
Keys must be hashable: numbers, strings, and tuples of hashable items work; lists do not.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-5}{}
\begin{pyex}
seen = {4: 0}
4 in seen, seen.get(9, -1)            # -> (True, -1)
seen[7] = 1
list(seen.items()), list(seen.values()) # -> ([(4, 0), (7, 1)], [0, 1])
del seen[4]
seen                                  # -> {7: 1}
cells = {(0, 1)}
cells.add((2, 3))
cells.discard((9, 9))                 # absent is allowed
cells.remove((0, 1))                 # absent would raise KeyError
cells                                 # -> {(2, 3)}
{1, 2} & {2, 3}, {1, 2} | {2, 3}    # -> ({2}, {1, 2, 3})
{1, 2} - {2, 3}                      # -> {1}
\end{pyex}
\hypertarget{example-end-5}{}
\end{minipage}\par
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-6}{}
\begin{pyex}
from collections import Counter, defaultdict
count = Counter("aba")
count["a"], count["z"]                # -> (2, 0)
Counter("aab") == Counter("aba")      # -> True
groups = defaultdict(list)            # factory: no parentheses
for word in ["eat", "tea", "tan"]:
    groups["".join(sorted(word))].append(word)
list(groups.values())                # -> [['eat', 'tea'], ['tan']]
\end{pyex}
\hypertarget{example-end-6}{}
\end{minipage}\par
\cd{defaultdict} inserts a default on \cd{d[key]}, but not on \cd{d.get(key)}.
Do not add or delete keys while iterating a dictionary or set. Iterate a snapshot such as \cd{list(d)} if needed.

\subsection{Strings and ordering}
Strings are immutable. Collect output pieces, then join them.
\cd{sorted(s)} returns a character list. Tuples compare from left to right.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-7}{}
\begin{pyex}
s = "A man, 12!"
"".join(ch.lower() for ch in s if ch.isalnum()) # -> 'aman12'
"a b  c".split(), "a,b,,c".split(",") # -> (['a', 'b', 'c'], ['a', 'b', '', 'c'])
"12#abc".find("#"), int("12"), str(12) # -> (2, 12, '12')
ord("c") - ord("a"), chr(ord("a") + 2) # -> (2, 'c')
"ab" in "zabc", "abc".startswith("ab") # -> (True, True)
f"{3}#{'cat'}"                       # -> '3#cat'
sorted([3, 1, 2], reverse=True)        # -> [3, 2, 1]
items = [(1, 2), (0, 8), (1, 5)]
sorted(items, key=lambda p: (p[0], -p[1]))
# -> [(0, 8), (1, 5), (1, 2)]
min(items, key=lambda p: p[1])         # -> (1, 2)
(1, 8) < (2, 0)                      # -> True
nums = [3, 1, 2]
result = nums.sort()
nums, result                          # -> ([1, 2, 3], None)
\end{pyex}
\hypertarget{example-end-7}{}
\end{minipage}\par
\cd{sorted} makes a new list. \cd{sort} and \cd{reverse} change the list and return \cd{None}.
Keep original indexes with \cd{enumerate} if you must restore output order.

\subsection{Queues, heaps, and bisection}
Use \cd{deque} for FIFO. A heap returns its smallest item; its whole list is not sorted.
Negate numeric priorities for largest-first selection.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-8}{}
\begin{pyex}
from collections import deque
from heapq import heapify, heappush, heappop
q = deque([1, 2])
q.append(3)
q.popleft(), q[-1]                   # -> (1, 3)
h = [5, 1, 3]
heapify(h)                            # O(n), changes h
h[0]                                  # -> 1
heappush(h, 2)
[heappop(h) for _ in range(4)]        # -> [1, 2, 3, 5]
h = [-5, -1, -3]
heapify(h)
-heappop(h)                          # -> 5
\end{pyex}
\hypertarget{example-end-8}{}
\end{minipage}\par
Heap tuples compare each field. Use \cd{(priority, unique_id, node)} when nodes cannot be ordered.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-9}{}
\begin{pyex}
from bisect import bisect_left, bisect_right
a = [1, 2, 2, 4]
bisect_left(a, 2), bisect_right(a, 2)  # -> (1, 3)
bisect_left(a, 3), bisect_right(a, 9)  # -> (3, 4)
i = bisect_right(a, 3) - 1            # last value <= 3
a[i] if i >= 0 else None             # -> 2
\end{pyex}
\hypertarget{example-end-9}{}
\end{minipage}\par
\cd{bisect_left} finds the first value at least \cd{x}; \cd{bisect_right} finds the first value greater than \cd{x}.
Either can return \cd{len(a)}. Search is logarithmic; insertion in the middle is still linear.

\subsection{Helpers, scope, caching, and classes}
A missing return gives \cd{None}. A helper can read outer names and change outer containers.
Use \cd{nonlocal} when it reassigns an outer variable.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-10}{}
\begin{pyex}
def count_positive(nums):
    total, found = 0, []
    def visit(x):
        nonlocal total
        if x > 0:
            total += 1
            found.append(x)           # append needs no nonlocal
    for x in nums:
        visit(x)
    return total, found
count_positive([-1, 2, 3])            # -> (2, [2, 3])

from functools import cache
def stairs(n):
    @cache
    def ways(i):                      # fresh cache for each stairs call
        if i <= 1:
            return 1
        return ways(i - 1) + ways(i - 2)
    return ways(n)
stairs(4)                             # -> 5
\end{pyex}
\hypertarget{example-end-10}{}
\end{minipage}\par
Cache keys must be hashable. Include every value that changes the future answer.
Do not change hidden state on which a cached answer depends.
A cache does not remove recursion depth. Use a table, stack, or queue for deep chains.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-11}{}
\begin{pyex}
class Node:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next
head = Node(3, Node(5))
head.val, head.next.val               # -> (3, 5)
\end{pyex}
\hypertarget{example-end-11}{}
\end{minipage}\par
\cd{self} is the current instance. Put per-instance containers in \cd{__init__}.
For \cd{class Solution}, the judge calls your method with its supplied arguments.
\cd{List[int]} and \cd{list[int]} are type hints; they do not convert or check values.
Avoid mutable defaults such as \cd{path=[]}. Allocate the list inside the function.

\subsection{Arithmetic and costs}
Python integers grow as needed. \cd{/} produces a float; \cd{//} rounds down.
For positive integers, use an integer formula for ceiling division.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-12}{}
\begin{pyex}
7 // 3, 7 % 3, divmod(7, 3)          # -> (2, 1, (2, 1))
-7 // 3, -7 % 3                     # -> (-3, 2)
(11 + 4 - 1) // 4                    # -> 3
float("inf") > 10**100              # -> True
\end{pyex}
\hypertarget{example-end-12}{}
\end{minipage}\par
To truncate division toward zero, divide magnitudes with \cd{//}, then apply the sign.
For Reverse Polish Notation, \(-7/3\) must give \(-2\). Avoid float conversion.
\begin{longtable}{@{}L{7.8cm}L{8.2cm}@{}}
\toprule Operation & Cost \\ \midrule\endhead
List index, assignment, end pop & \(O(1)\).\\
List append & Amortized \(O(1)\).\\
Dictionary/set lookup, insert, delete & Average \(O(1)\), plus key construction and hashing.\\
\cd{x in list}, \cd{index}, \cd{min}, \cd{max}, \cd{sum} & \(O(n)\).\\
Copy or slice of \(k\) elements & \(O(k)\) time and space.\\
Sort & \(O(n\log n)\) worst-case comparisons.\\
Heap push/pop; heap construction & \(O(\log n)\); \(O(n)\).\\
Deque operations at either end & \(O(1)\).\\
\bottomrule
\end{longtable}
Repeated slicing, concatenation, or \cd{max(count.values())} can add work.
The last operation is cheap for a fixed alphabet of 26 letters, but not for a growing set of keys.

\section{Hashing: ask an exact question}\label{sec:hash}
Use a set for ``did it occur?'', a dictionary for ``where?'', and counts for ``how many?''.
A large value range is fine: store only keys that occur.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-13}{}
\begin{pyex}
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
two_sum([3, 3], 6)                    # -> [0, 1]
\end{pyex}
\hypertarget{example-end-13}{}
\end{minipage}\par
Before index \cd{i}, the map contains only earlier items. Look up before insertion so that an item cannot pair with itself.
For a pair count, add \cd{count[target - x]} to the answer, then increase \cd{count[x]}.
For Contains Duplicate, only membership matters. For Valid Anagram, compare two \cd{Counter} objects.

\textbf{Group by what stays the same.} Anagrams have the same sorted characters.
The key is the sorted word joined back into a string; see the Python grouping example.
This costs \(O(L\log L)\) per word of length \(L\).
If a linear bound is required, count the fixed alphabet and use the count tuple as the key.
For Sudoku, a digit must be new to its row, column, and box. The box key is \cd{(r // 3, c // 3)}.

\textbf{Use a bounded property as an index.} A frequency is at most the input length.
This gives a direct way to return the top \cd{k} frequencies without sorting all values.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-14}{}
\begin{pyex}
from collections import Counter
def top_frequent(nums, k):
    buckets = [[] for _ in range(len(nums) + 1)]
    for value, count in Counter(nums).items():
        buckets[count].append(value)
    out = []
    for count in range(len(nums), 0, -1):
        out.extend(buckets[count])
        if len(out) >= k:
            return out[:k]
sorted(top_frequent([1, 1, 1, 2, 2, 3], 2)) # -> [1, 2]
\end{pyex}
\hypertarget{example-end-14}{}
\end{minipage}\par
For Longest Consecutive Sequence, put values in a set. Start a run only when \cd{x - 1} is absent.
Then increment while the next value exists. Iterate distinct values. Each run is scanned once in total.
\cost{Hash scans take average \(O(n)\) time and \(O(n)\) space.}
\transfer{Write the exact lookup key before choosing a hash table. To group equivalent objects, remove only the irrelevant detail.
If you need an inequality or nearest value, a plain hash lookup is insufficient; test sorting or binary search.}

\subsection{Recover boundaries with a length header}
Encode and Decode Strings is a parsing problem. A delimiter can occur inside the data.
Write the length, a marker, and the payload. Search for the marker only in the header; jump over the payload.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-15}{}
\begin{pyex}
def encode(words):
    return "".join(f"{len(w)}#{w}" for w in words)
def decode(data):
    out, i = [], 0
    while i < len(data):
        j = data.index("#", i)
        size = int(data[i:j])
        i = j + 1
        out.append(data[i:i + size])
        i += size
    return out
decode(encode(["", "2#x", "hello"]))   # -> ['', '2#x', 'hello']
decode(encode([]))                    # -> []
\end{pyex}
\hypertarget{example-end-15}{}
\end{minipage}\par
The decoder assumes valid encoder output. The same Python character count is used on both sides.
For a byte protocol, define lengths in bytes instead.

\section{Prefix and suffix: summarize each side}\label{sec:prefix}
Ask what a position needs from its left and right. Compute those summaries once.
For Product of Array Except Self, multiplying the two sides avoids division and handles zeros.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-16}{}
\begin{pyex}
def product_except_self(nums):
    out = [1] * len(nums)
    product = 1
    for i, x in enumerate(nums):
        out[i] = product              # strictly left of i
        product *= x
    product = 1
    for i in range(len(nums) - 1, -1, -1):
        out[i] *= product             # strictly right of i
        product *= nums[i]
    return out
product_except_self([1, 2, 3, 4])     # -> [24, 12, 8, 6]
product_except_self([0, 2, 0])        # -> [0, 0, 0]
\end{pyex}
\hypertarget{example-end-16}{}
\end{minipage}\par
For Trapping Rain Water, precompute the maximum height from each end.
At index \cd{i}, water is \cd{min(left_max[i], right_max[i]) - height[i]}.
Including \cd{height[i]} in each maximum makes this nonnegative.
For \cd{[3, 0, 2, 0, 4]}, the water depths are \cd{[0, 3, 1, 3, 0]}.
This clear \(O(n)\)-space version is the default; two pointers can reduce the storage if required.

\textbf{Transfer to range queries.} Use an empty prefix so that every range uses one formula.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-17}{}
\begin{pyex}
nums = [4, -2, 5]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
prefix[3] - prefix[1]                # -> 3
\end{pyex}
\hypertarget{example-end-17}{}
\end{minipage}\par
Here \cd{prefix[i]} summarizes \cd{nums[:i]}. The prefix ending at \cd{right} includes the unwanted part before \cd{left}.
Subtract that earlier prefix to leave only the sum on \cd{[left, right)}: \cd{prefix[right] - prefix[left]}.
If a new task asks for a count of exact-sum ranges, rearrange the equation and count earlier prefixes with hashing.
\cost{Two passes take \(O(n)\) time. Product Except Self uses \(O(1)\) extra space beyond its output.}
\transfer{Choose the summary from the operation: sum, product, minimum, maximum, or last occurrence.
Only use subtraction to remove a prefix when the operation supports it; prefix maxima cannot be subtracted.}

\section{Two pointers: justify what you discard}\label{sec:pointers}
In a sorted pair search, the smallest and largest remaining values bound all other choices.
If their sum is too small, no pair using the left value can work. If too large, no pair using the right value can work.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-18}{}
\begin{pyex}
def sorted_pair(a, target):
    left, right = 0, len(a) - 1
    while left < right:
        total = a[left] + a[right]
        if total < target:
            left += 1
        elif total > target:
            right -= 1
        else:
            return [left + 1, right + 1]  # required 1-based indexes
    return []
sorted_pair([2, 7, 11, 15], 9)        # -> [1, 2]
\end{pyex}
\hypertarget{example-end-18}{}
\end{minipage}\par
For 3Sum, sort, fix one anchor, then search its suffix for the opposite sum.
Skip equal anchors. After a match, move both pointers and skip equal values at each end.
This avoids duplicate triples while still allowing repeated values at different indexes.
The sort costs \(O(n\log n)\); the pair scans cost \(O(n^2)\).

For Container With Most Water, record \cd{min(height[left], height[right]) * (right - left)}.
Move the shorter wall. Keeping it and moving the taller wall can only reduce width without improving the limiting height.
For \cd{[1, 8, 6, 2, 5, 4, 8, 3, 7]}, the best pair has height 7 and width 7, giving 49.

For Valid Palindrome, keep lowercase alphanumeric characters and compare with the reverse.
If constant extra space is required, use two pointers that skip non-alphanumeric characters.
\cost{Each pointer moves in one direction, so an ordinary two-pointer pass takes \(O(n)\) time.}
\transfer{Explain why the discarded endpoint cannot be part of a better answer among the remaining choices.
If moving either end can lose a valid answer without such a proof, choose another method.}

\section{Sliding windows: maintain one contiguous range}\label{sec:window}
Use a window when neighboring ranges share almost all their work.
Choose the stored counts or candidates, then decide when the left end must move.

\subsection{Longest valid: shrink while invalid}
For a substring with no repeats, a set represents the current window.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-19}{}
\begin{pyex}
def longest_unique(s):
    seen, left, best = set(), 0, 0
    for right, ch in enumerate(s):
        while ch in seen:
            seen.remove(s[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best
longest_unique("pwwkew")              # -> 3
longest_unique("")                    # -> 0
\end{pyex}
\hypertarget{example-end-19}{}
\end{minipage}\par
For Character Replacement, store letter counts. A window needs
\(\text{length} - \text{largest count}\) replacements.
Shrink while that exceeds \cd{k}. Recompute the largest count over the 26 letters.
This keeps the rule exact and avoids the more subtle stale-maximum optimization.
For \cd{"AABABBA"} with \cd{k=1}, the answer is 4.

\subsection{Shortest sufficient: shrink while valid}
For Minimum Window Substring, track the number of required character copies still missing.
Negative counts mean surplus copies. Save indexes during the scan, then slice once.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-20}{}
\begin{pyex}
from collections import Counter
def min_window(s, t):
    if not t:
        return ""
    need, missing = Counter(t), len(t)
    left, best_start, best_size = 0, 0, len(s) + 1
    for right, ch in enumerate(s):
        if need[ch] > 0:
            missing -= 1
        need[ch] -= 1
        while missing == 0:
            if right - left + 1 < best_size:
                best_start, best_size = left, right - left + 1
            ch = s[left]
            need[ch] += 1
            if need[ch] > 0:
                missing += 1
            left += 1
    return "" if best_size > len(s) else s[best_start:best_start + best_size]
min_window("ADOBECODEBANC", "ABC")    # -> 'BANC'
min_window("a", "aa")                 # -> ''
\end{pyex}
\hypertarget{example-end-20}{}
\end{minipage}\par
For Permutation in String, the length is fixed at \cd{len(s1)}.
Add the new character, remove the outgoing character, and compare 26-element count arrays.
Equal counts mean a permutation. For \cd{"ab"} in \cd{"eidbaooo"}, the matching window is \cd{"ba"}.

\subsection{Keep only useful maximum candidates}
A newer value that is at least as large makes an older candidate useless: it is larger and expires later.
Store indexes in a deque, with decreasing values.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-21}{}
\begin{pyex}
from collections import deque
def window_max(nums, k):
    q, out = deque(), []
    for i, x in enumerate(nums):
        while q and q[0] <= i - k:
            q.popleft()              # expired
        while q and nums[q[-1]] <= x:
            q.pop()                  # dominated
        q.append(i)
        if i >= k - 1:
            out.append(nums[q[0]])
    return out
window_max([1, 3, -1, -3, 5, 3, 6, 7], 3) # -> [3, 3, 5, 5, 6, 7]
\end{pyex}
\hypertarget{example-end-21}{}
\end{minipage}\par
\cost{Each item enters and leaves at most once: \(O(n)\) time, apart from fixed-alphabet comparisons.}
\transfer{Check that validity gives a safe direction for the left pointer.
With negative values, removing a left value can increase a sum; a usual sum-limit window may fail.
For a fixed length, identify an updateable summary. For an extremum, test whether newer candidates dominate older ones.}

\section{Stacks: keep unfinished work}\label{sec:stack}
Use a stack when the most recent unfinished item must be handled first.
For brackets, push openers; a closer must match the top. Finish with an empty stack.
For reverse Polish notation, pop the right operand first, then the left.

def trunc_div(a, b):

    return -magnitude if (a < 0) != (b < 0) else magnitude

\subsection{Monotonic stack: resolve waiting items}
For Daily Temperatures, each index waits for its first strictly warmer day.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-23}{}
\begin{pyex}
def warmer_days(temperatures):
    waiting, out = [], [0] * len(temperatures)
    for i, value in enumerate(temperatures):
        while waiting and temperatures[waiting[-1]] < value:
            j = waiting.pop()
            out[j] = i - j
        waiting.append(i)
    return out
warmer_days([73, 74, 75, 71, 69, 72, 76, 73]) # -> [1, 1, 4, 2, 1, 1, 0, 0]
\end{pyex}
\hypertarget{example-end-23}{}
\end{minipage}\par
The top is the most recent unresolved index. Equal temperatures do not resolve a day.
Each index is pushed and popped once.

For Largest Rectangle in Histogram, a shorter bar closes the rectangles that taller bars could extend.
Store each height with the earliest start where it is valid. A final zero flushes the stack.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-24}{}
\begin{pyex}
def largest_rectangle(heights):
    stack, best = [], 0
    for i, height in enumerate(heights + [0]):
        start = i
        while stack and stack[-1][1] > height:
            start, old_height = stack.pop()
            best = max(best, old_height * (i - start))
        stack.append((start, height))
    return best
largest_rectangle([2, 1, 5, 6, 2, 3]) # -> 10
largest_rectangle([2, 2])            # -> 4
\end{pyex}
\hypertarget{example-end-24}{}
\end{minipage}\par
For Car Fleet, sort cars from nearest to farthest from the target.
Compute each solo arrival time. If it is no greater than the fleet time ahead, it joins that fleet.
Otherwise it starts a new fleet. You need only the last fleet time and a count.
\cost{Monotonic scans take \(O(n)\) time and \(O(n)\) space. Car Fleet also needs sorting.}
\transfer{Name the event that finishes a pending item. Then choose strict or non-strict comparison from the requested relation.
A stack is useful only when resolving the most recent item also lets you resolve older ones in order.}

\section{Binary search: find a boundary}\label{sec:search}
The goal is to discard many candidates after one test. This is safe when a successful midpoint also makes every larger candidate successful.
That condition is monotonicity: false values followed by true values.
Keep a half-open search range \cd{[lo, hi)}. Return its first true index, or the original \cd{hi} if none exists.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-25}{}
\begin{pyex}
def first_true(lo, hi, test):
    while lo < hi:
        mid = (lo + hi) // 2
        if test(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

a = [1, 2, 2, 4]
first_true(0, len(a), lambda i: a[i] >= 2) # -> 1
first_true(0, len(a), lambda i: a[i] >= 9) # -> 4

def eating_speed(piles, hours):
    def fits(speed):
        return sum((p + speed - 1) // speed for p in piles) <= hours
    return first_true(1, max(piles) + 1, fits)
eating_speed([3, 6, 7, 11], 8)        # -> 4
\end{pyex}
\hypertarget{example-end-25}{}
\end{minipage}\par
For exact search, find the first value at least the target, then check equality and bounds.
For Search a 2D Matrix, use a virtual sorted list: flat index \cd{i} maps to \cd{divmod(i, cols)}.
For TimeMap, append timestamps in their guaranteed increasing order. Use \cd{bisect_right(times, t) - 1} for the latest eligible value.

\textbf{Rotated arrays.} With distinct values, \cd{nums[i] <= nums[-1]} is false on the high run and true on the low run.
Its first true index is the minimum. For rotated exact search, find this pivot, choose the sorted side that can contain the target,
then run ordinary boundary search there. For \cd{[4, 5, 1, 2, 3]}, the pivot is 2.

\subsection{A partition instead of a value}
Median of Two Sorted Arrays explicitly requires logarithmic time.
Choose how many values the shorter array contributes to the left half. The other count is then fixed.
Only the two values on each side of each cut matter.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-26}{}
\begin{pyex}
def median_sorted(a, b):
    if len(a) > len(b):
        a, b = b, a
    half = (len(a) + len(b) + 1) // 2
    lo, hi = 0, len(a)
    while lo <= hi:
        i = (lo + hi) // 2
        j = half - i
        al = a[i - 1] if i else float("-inf")
        ar = a[i] if i < len(a) else float("inf")
        bl = b[j - 1] if j else float("-inf")
        br = b[j] if j < len(b) else float("inf")
        if al > br:
            hi = i - 1               # too many from a
        elif bl > ar:
            lo = i + 1               # too few from a
        elif (len(a) + len(b)) % 2:
            return max(al, bl)
        else:
            return (max(al, bl) + min(ar, br)) / 2
median_sorted([1, 3], [2])            # -> 2
median_sorted([], [1, 2])             # -> 1.5
\end{pyex}
\hypertarget{example-end-26}{}
\end{minipage}\par
The left half contains the extra value when the total is odd. At a valid cut, both left boundary values are no greater than both right boundary values.
\cost{Boundary search uses \(O(\log R)\) tests. Include the cost of each test. Koko costs \(O(n\log M)\).}
\transfer{Write the yes-or-no test and prove why it changes only once.
The search variable can be an index, a speed, a capacity, or a partition size. Sorting alone does not prove an arbitrary predicate is monotonic.}

\section{Linked lists: preserve links before changing them}\label{sec:linked}
A pointer is a reference to a node. Changing \cd{cur.next} changes the structure; moving \cd{cur} changes only your local reference.
Save the forward link before reversing it. A dummy node gives the head an ordinary predecessor.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-27}{}
\begin{pyex}
class Node:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next
def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    return prev
head = reverse(Node(1, Node(2, Node(3))))
head.val, head.next.val, head.next.next.val # -> (3, 2, 1)
\end{pyex}
\hypertarget{example-end-27}{}
\end{minipage}\par
For Merge Two Sorted Lists, keep a dummy and a tail. Link the smaller head after the tail, advance that input, and move the tail.
When one input ends, attach the other remainder. Return \cd{dummy.next}.

For Remove Nth From End, set \cd{slow=dummy} and \cd{fast=head}.
Advance \cd{fast} by \cd{n} nodes, then move both until \cd{fast is None}.
Now \cd{slow.next} is the target. Set \cd{slow.next = slow.next.next}.
The gap converts a distance from the end into a position from the front.

For Reorder List, the simplest direct representation is an array of node references.
Relink them in the order first, last, second, second-last. Set the final \cd{next} to \cd{None}.
If constant extra space is required, find the middle, split the list, reverse the second half, and alternate the two halves.

\subsection{Reverse a complete group}
First prove that \cd{k} nodes exist. Leave an incomplete tail alone.
Start \cd{prev} at the node after the group, so reversal already connects the new tail to the remainder.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-28}{}
\begin{pyex}
class Node:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next
def reverse_groups(head, k):
    dummy = before = Node(0, head)
    while True:
        last = before
        for _ in range(k):
            last = last.next
            if last is None:
                return dummy.next
        after = last.next
        old_first = before.next
        prev, cur = after, old_first
        while cur is not after:
            nxt = cur.next
            cur.next = prev
            prev, cur = cur, nxt
        before.next = last
        before = old_first
head = reverse_groups(Node(1, Node(2, Node(3))), 2)
head.val, head.next.val, head.next.next.val # -> (2, 1, 3)
\end{pyex}
\hypertarget{example-end-28}{}
\end{minipage}\par

\subsection{Cycles and copies}
Floyd's cycle test uses a slow pointer and a pointer that moves twice as fast.
If a cycle exists, their relative distance changes by one step each round, so they meet.
For a linked list, stop safely when \cd{fast} or \cd{fast.next} is absent.

Find the Duplicate Number requires an unchanged array and constant extra space.
Read \cd{i -> nums[i]} as a next-pointer function. Index 0 cannot be a target, and values lie in \cd{1..n}.
The cycle entrance has two incoming paths, so its index is the duplicate value.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-29}{}
\begin{pyex}
def duplicate(nums):
    slow = fast = 0
    while True:
        slow = nums[slow]
        fast = nums[nums[fast]]
        if slow == fast:
            break
    start = 0
    while start != slow:
        start = nums[start]
        slow = nums[slow]
    return start
duplicate([1, 3, 4, 2, 2])           # -> 2
\end{pyex}
\hypertarget{example-end-29}{}
\end{minipage}\par
If the entrance is \(\mu\) steps from the start and the cycle length is \(\lambda\), the slow pointer's step count at the meeting is a multiple of \(\lambda\).
Moving one pointer from the start and one from the meeting makes them meet at the entrance after \(\mu\) steps.

For Copy List With Random Pointer, make \cd{copies = {None: None}}.
Pass 1 creates every copied node. Pass 2 sets each copy's \cd{next} and \cd{random} by map lookup.
Copy node identities, not values: equal values can belong to different nodes.

\subsection{LRU: lookup plus recency order}
Use \cd{OrderedDict} for the clearest Python implementation.
Every successful read and every write moves the key to the most recent end.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-30}{}
\begin{pyex}
from collections import OrderedDict
class LRUCache:
    def __init__(self, capacity):
        self.capacity, self.data = capacity, OrderedDict()
    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]
    def put(self, key, value):
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
cache = LRUCache(2)
cache.put(1, 10)
cache.put(2, 20)
cache.get(1)                          # -> 10
cache.put(3, 30)
cache.get(2)                          # -> -1
\end{pyex}
\hypertarget{example-end-30}{}
\end{minipage}\par
If asked to build the structure, use a dictionary from keys to doubly linked nodes, with head and tail sentinels.
Remove a node with \cd{node.prev.next = node.next} and \cd{node.next.prev = node.prev}.
Insert at the recent end by reconnecting both neighboring links. The map supplies the node directly.
\cost{Ordinary list passes take \(O(n)\). LRU reads and writes take average \(O(1)\).}
\transfer{Use a dummy for changes at the head, a saved successor for rewiring, and a map for cross-links.
When a design needs two operations, combine structures that supply those operations.}

\section{Trees: decide what travels up or down}\label{sec:tree}
If an answer needs ancestor information, carry it down. If it needs child answers, combine them on the way up.
Use a level frontier when the output groups nodes by distance from the root.

\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-31}{}
\begin{pyex}
class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right
def levels(root):
    frontier, out = [root] if root else [], []
    while frontier:
        out.append([node.val for node in frontier])
        frontier = [child for node in frontier
                    for child in (node.left, node.right) if child]
    return out
root = Node(1, Node(2), Node(3, Node(4)))
levels(root)                          # -> [[1], [2, 3], [4]]
\end{pyex}
\hypertarget{example-end-31}{}
\end{minipage}\par
The number of levels is maximum depth. The last value of each level is the right side view.
For Good Nodes, stack entries are \cd{(node, largest_ancestor)}; count a node when its value is at least that maximum.
For Invert Tree, swap the children at every visited node.

\subsection{Combine children without deep recursion}
Recursion expresses the idea cleanly, but these problems allow long chains.
Collect nodes with parents before children, then reverse that order. Both child results exist before the parent is processed.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-32}{}
\begin{pyex}
class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right
def tree_summary(root):
    if root is None:
        return 0, True, 0
    order, stack = [], [root]
    while stack:
        node = stack.pop()
        order.append(node)
        stack.extend(c for c in (node.left, node.right) if c)
    height = {None: 0}
    balanced, diameter = True, 0
    for node in reversed(order):
        left, right = height[node.left], height[node.right]
        height[node] = 1 + max(left, right)
        balanced = balanced and abs(left - right) <= 1
        diameter = max(diameter, left + right)
    return height[root], balanced, diameter
root = Node(1, Node(2, Node(4)), Node(3))
tree_summary(root)                    # -> (3, True, 3)
\end{pyex}
\hypertarget{example-end-32}{}
\end{minipage}\par
Height counts nodes; diameter counts edges. The path through a node has \cd{left_height + right_height} edges.
Compute only the summary needed by the actual problem.

For Maximum Path Sum, use the same order with \cd{gain[None] = 0}.
Clamp each child gain to zero. A candidate path is \cd{node.val + left_gain + right_gain}.
The gain returned upward is \cd{node.val + max(left_gain, right_gain)}: a path sent to a parent cannot branch.
Initialize the global best to negative infinity so that an all-negative tree still chooses one node.
For \cd{[-10, 9, 20, None, None, 15, 7]}, the best path is \(15+20+7=42\).

\subsection{Use shape and order precisely}
\begin{longtable}{@{}L{4.4cm}L{11.6cm}@{}}
\toprule Task & Information to keep \\ \midrule\endhead
Same Tree & Visit node pairs. Two absent nodes match. One absent node or unequal values fails. Compare both child pairs.\\
Subtree & Try each node as a root and apply Same Tree. Use explicit stacks for deep inputs. This direct \(O(nm)\) method fits these sizes.\\

Skip empty ranges. Otherwise create the root, then schedule right before left so the next job consumes the left preorder root.\\

\end{longtable}
For example, serializing a root 1 with only a right child 2 gives \cd{"1,N,2,N,N"} in this BFS format.
For repeated kth-smallest queries with updates, maintain subtree sizes: the left size tells you which side contains rank \cd{k}.
\cost{Most traversals take \(O(n)\) time. The explicit bottom-up summary uses \(O(n)\) space.}
\transfer{Define the helper's return value before its code. Ask whether the parent needs one branch or both.
For ordered trees, propagate the full ancestor restriction. For a new tree aggregate, change the per-node combination.}

\section{Tries: share work across prefixes}\label{sec:trie}
A trie stores one character per edge. Words with a common prefix share that path.
A terminal marker distinguishes a whole word from a prefix. A dictionary of dictionaries is enough here.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-33}{}
\begin{pyex}
def insert(root, word):
    node = root
    for ch in word:
        node = node.setdefault(ch, {})
    node["$"] = word                 # safe: input uses lowercase letters
def walk(root, text):
    node = root
    for ch in text:
        if ch not in node:
            return None
        node = node[ch]
    return node
root = {}
insert(root, "apple")
walk(root, "app") is not None         # -> True
"$" in walk(root, "app")              # -> False
"$" in walk(root, "apple")            # -> True
\end{pyex}
\hypertarget{example-end-33}{}
\end{minipage}\par
\cd{setdefault(key, value)} inserts \cd{value} only if the key is absent, then returns the stored value.
Search checks the terminal marker. \cd{startsWith} only checks whether the walk succeeds.

For WordDictionary, a literal follows one edge. A dot tries each character child at that position.
The pattern must end at a terminal node.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-34}{}
\begin{pyex}
def matches(root, pattern):
    def search(node, i):
        if i == len(pattern):
            return "$" in node
        ch = pattern[i]
        if ch == ".":
            return any(search(child, i + 1)
                       for key, child in node.items() if key != "$")
        return ch in node and search(node[ch], i + 1)
    return search(root, 0)
root = {"b": {"a": {"d": {"$": "bad"}}}}
matches(root, ".ad"), matches(root, "b.") # -> (True, False)
\end{pyex}
\hypertarget{example-end-34}{}
\end{minipage}\par
For Word Search II, put all words in one trie. Combine a grid path with a trie node.
If the cell's letter is not a child, stop: no stored word can use that prefix.
Mark the cell for the current path, explore neighbors, then restore it.
On a terminal marker, save the word and remove that marker so it is reported once.
After returning from a child, delete its edge if the child dictionary is empty.
This removes exhausted prefixes without reference counters.
\cost{Insert and literal lookup take \(O(L)\) per word. Wildcards and grid paths can branch; prefix pruning avoids irrelevant branches.}
\transfer{Use a trie when many queries or candidate words share prefixes.
Combine it with a second search only when both searches must advance through the same characters.}

\section{Heaps: keep the next useful candidate}\label{sec:heap}
A heap answers ``which candidate is best next?'' without sorting after each update.
For the kth largest value, keep the largest \cd{k} seen so far in a min-heap.
Its smallest value is the weakest retained candidate.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-35}{}
\begin{pyex}
from heapq import heappush, heappop
def kth_largest(nums, k):
    heap = []
    for x in nums:
        heappush(heap, x)
        if len(heap) > k:
            heappop(heap)
    return heap[0]
kth_largest([3, 2, 1, 5, 6, 4], 2)    # -> 5
\end{pyex}
\hypertarget{example-end-35}{}
\end{minipage}\par
For a stream, preserve the heap between \cd{add} calls. For K Closest Points, sorting by \cd{x*x + y*y} and slicing is the simplest default.
For Last Stone Weight, pop the two largest weights from a heap of negatives and push their difference if nonzero.

\subsection{Two heaps expose the middle}
Keep the lower half in a max-heap and the upper half in a min-heap.
All lower values must be no greater than all upper values.
Keep equal sizes, or one extra value in the lower half.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-36}{}
\begin{pyex}
from heapq import heappush, heappop
class MedianFinder:
    def __init__(self):
        self.low, self.high = [], []
    def addNum(self, x):
        heappush(self.low, -x)
        heappush(self.high, -heappop(self.low))
        if len(self.high) > len(self.low):
            heappush(self.low, -heappop(self.high))
    def findMedian(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2
finder = MedianFinder()
finder.addNum(1)
finder.addNum(2)
finder.findMedian()                   # -> 1.5
finder.addNum(3)
finder.findMedian()                   # -> 2
\end{pyex}
\hypertarget{example-end-36}{}
\end{minipage}\par

\subsection{Merge streams and enforce cooldowns}
For Merge K Sorted Lists, put one front node from each nonempty list in a heap as \cd{(value, list_id, node)}.
Pop the smallest, append it, then push its successor from the same list.
Only that list's next candidate changes.

Twitter is the same merge in reverse time. Append \cd{(timestamp, tweet_id)} to each author's list.
Store followees in a set. A feed merges the user's own list and each followed list.
Heap entries are \cd{(-timestamp, user_id, index)}. Pop at most ten tweets; after each pop, push that author's next older index.
Follow uses \cd{add}; unfollow uses \cd{discard}. Unique timestamps resolve ties.

For Task Scheduler, fill a round of \cd{cooldown + 1} slots with distinct tasks of largest remaining frequency.
Hold their updated counts outside the heap until the round ends.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-37}{}
\begin{pyex}
from collections import Counter
from heapq import heapify, heappop, heappush
def schedule_length(tasks, cooldown):
    heap = [-count for count in Counter(tasks).values()]
    heapify(heap)
    elapsed = 0
    while heap:
        pending, used = [], 0
        for _ in range(cooldown + 1):
            if not heap:
                break
            remaining = heappop(heap) + 1
            used += 1
            if remaining:
                pending.append(remaining)
        for remaining in pending:
            heappush(heap, remaining)
        elapsed += cooldown + 1 if heap else used
    return elapsed
schedule_length(list("AAABBB"), 2)    # -> 8
\end{pyex}
\hypertarget{example-end-37}{}
\end{minipage}\par
The remaining heap after reinsertion means another round is needed, so this round includes idle slots.
For \cd{AAABBB} and cooldown 2, the rounds are \cd{AB_ | AB_ | AB}, giving 8 slots.
Fill the highest remaining frequencies first so repeated work is spread across rounds. The final round needs no trailing idle time.
\cost{A size-\(k\) heap costs \(O(n\log(k+1))\). A merge of \(k\) streams costs \(O(N\log(k+1))\). Median insertion is \(O(\log n)\).}
\transfer{Choose the heap key from the next decision, not from the input format.
Keep only one front per sorted stream. If old candidates can expire, remove invalid heap tops before using them.}

\section{Backtracking: choose, explore, undo}\label{sec:backtrack}
Use backtracking when you need to enumerate choices or find a valid arrangement.
The state must describe the partial answer and what choices remain.
Use a start index when order does not matter. Use unused items when order does matter.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-38}{}
\begin{pyex}
def combinations(candidates, target):
    candidates = sorted(candidates)
    out, path = [], []
    def search(start, remaining):
        if remaining == 0:
            out.append(path.copy())
            return
        for i in range(start, len(candidates)):
            x = candidates[i]
            if x > remaining:
                break
            path.append(x)
            search(i, remaining - x)  # same index allows reuse
            path.pop()
    search(0, target)
    return out
combinations([2, 3, 6, 7], 7)        # -> [[2, 2, 3], [7]]
\end{pyex}
\hypertarget{example-end-38}{}
\end{minipage}\par
For Combination Sum II, recurse with \cd{i + 1}, and skip when \cd{i > start and a[i] == a[i-1]}.
This skips duplicate choices at the same depth, while allowing equal values at different depths.
The early break requires sorted positive values.

\begin{longtable}{@{}L{4.4cm}L{11.6cm}@{}}
\toprule Choice structure & Minimal change \\ \midrule\endhead
Subsets & Start with \cd{[[]]}. For each value, extend with \cd{[part + [x] for part in out]}. The right side is built before extension.\\
Subsets with duplicates & Sort. Save the current path at each call; loop from \cd{start}, skip equal same-depth choices, recurse at \cd{i+1}.\\
Permutations & Pick each remaining item in turn; recurse on the remaining pool. Save the path when the pool is empty.\\
Phone letters & Start with \cd{[""]}. For each digit, form all old prefixes plus each mapped letter.\\
Generate parentheses & Track opens and closes. Add an opener if \cd{opens < n}; add a closer if \cd{closes < opens}. Save at length \cd{2*n}.\\
Palindrome partitions & Try every next piece \cd{s[start:end]}. Continue only if it equals its reverse. Save when \cd{start == len(s)}.\\
N-Queens & Place one queen per row. Track used columns and diagonal keys \cd{r-c}, \cd{r+c}. Mark before recursion; remove after it.\\
\bottomrule
\end{longtable}
Examples: \cd{[1,2]} gives subsets \cd{[[],[1],[2],[1,2]]}.
Digits \cd{"23"} give the nine pairs from \cd{"abc"} and \cd{"def"}.
For a 4-by-4 queens board, columns \cd{[1,3,0,2]} form one valid arrangement.

\subsection{A grid path owns its visited cells}
Word Search cannot reuse a cell in one word. Mark cells for the current path, then undo the mark even when a child succeeds.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-39}{}
\begin{pyex}
def word_exists(board, word):
    rows, cols = len(board), len(board[0])
    used = set()
    def search(r, c, i):
        if i == len(word):
            return True
        if not (0 <= r < rows and 0 <= c < cols):
            return False
        if (r, c) in used or board[r][c] != word[i]:
            return False
        used.add((r, c))
        found = any(search(r + dr, c + dc, i + 1)
                    for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)])
        used.remove((r, c))
        return found
    return any(search(r, c, 0) for r in range(rows) for c in range(cols))
word_exists([list("AB"), list("CD")], "ABD") # -> True
word_exists([list("AB")], "ABA")      # -> False
\end{pyex}
\hypertarget{example-end-39}{}
\end{minipage}\par
\cost{Search can be exponential. Estimate branch count, depth, and the unavoidable output size.}
\transfer{Decide whether choices are distinct by position, value, or order.
Prune only when no completion can work. If many branches reach the same future state and only a count or optimum is needed, test DP instead.}

\section{Graph traversal: choose the state and the frontier}\label{sec:graph}
A graph can be an adjacency list, a grid, or a set of legal transformations.
DFS explores with a stack. BFS explores with a queue and gives shortest paths when every move costs the same.
Mark a state when adding it to the frontier so that it is added once.

\subsection{A component is one complete flood}
Scan all possible starts. Each unvisited start begins a new connected component.
This version sinks land as it visits it, so it changes the grid.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-40}{}
\begin{pyex}
def island_sizes(grid):
    rows, cols = len(grid), len(grid[0])
    sizes = []
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != 1:
                continue
            grid[r][c] = 0
            stack, size = [(r, c)], 0
            while stack:
                x, y = stack.pop()
                size += 1
                for dx, dy in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                    a, b = x + dx, y + dy
                    if 0 <= a < rows and 0 <= b < cols and grid[a][b] == 1:
                        grid[a][b] = 0
                        stack.append((a, b))
            sizes.append(size)
    return sizes
island_sizes([[1, 1, 0], [0, 0, 1]])  # -> [2, 1]
\end{pyex}
\hypertarget{example-end-40}{}
\end{minipage}\par
Number of Islands uses string cells \cd{"1"} and \cd{"0"}; adjust the two literals.
Max Area of Island uses integer cells; return the largest size, or 0 if none.
For graph components, build \cd{adj = [[] for _ in range(n)]}, add both directions, and use a visited array.
Include isolated nodes in the outer scan.

\textbf{Reverse the question when there are many starts.}
For Pacific Atlantic, flood inland from each ocean border, moving to equal or higher neighbors.
Intersect the two reached sets. The reverse move represents a forward downhill path.
For Surrounded Regions, flood border-connected \cd{"O"} cells as safe, then flip only the remaining \cd{"O"} cells.

\subsection{Many sources, one BFS}
To find distance to the nearest gate, seed all gates at distance zero.
Every unfilled neighbor receives the current distance plus one.

\hypertarget{example-start-41}{}

from collections import deque
def fill_distances(rooms):
    rows, cols, INF = len(rooms), len(rooms[0]), 2**31 - 1

              if rooms[r][c] == 0)

        r, c = q.popleft()
        for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
            a, b = r + dr, c + dc

\end{pyex}
\hypertarget{example-end-41}{}
\end{minipage}\par
For Rotting Oranges, start with all rotten cells and count fresh cells.
Process \cd{len(q)} items per round; only then increase minutes.
Stop when fresh is zero or the queue is empty. Return \(-1\) if fresh cells remain; return 0 if none were fresh initially.

Word Ladder is BFS on words. A neighbor changes one character and belongs to the unvisited word set.
Remove words when enqueuing. Start the sequence length at 1 because the output counts words, not edges.
Alternatively, group words by a one-character wildcard key and clear each bucket after using it.

\textbf{Clone Graph.} A map from original node to copied node is also the visited structure.
Create and record a copy before processing its neighbors, so a cycle finds the existing copy.
Append the neighbor copies in the original edge order. An absent start returns \cd{None}.
\cost{An adjacency-list traversal takes \(O(V+E)\) time. A four-neighbor grid traversal takes \(O(RC)\).}
\transfer{List the facts that define a state. If arriving at the same location with a different key, budget, or move count changes the future,
that fact belongs in the state. Global visited marks mean ``this state is finished''; backtracking marks mean ``this path owns it for now''.}

\section{Graph structure: readiness and connectivity}\label{sec:structure}
\subsection{Topological order: take what is ready}
An edge \cd{u -> v} means \cd{u} must happen first. Indegree counts unmet prerequisites.
Removing a ready node reduces its dependents' counts.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-42}{}
\begin{pyex}
from collections import deque
def topological_order(n, edges):
    adj = [[] for _ in range(n)]
    indegree = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indegree[v] += 1
    q = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                q.append(v)
    return order if len(order) == n else []
topological_order(3, [(0, 1), (1, 2)]) # -> [0, 1, 2]
topological_order(2, [(0, 1), (1, 0)]) # -> []
\end{pyex}
\hypertarget{example-end-42}{}
\end{minipage}\par
For Course Schedule input \cd{[course, prerequisite]}, add \cd{prerequisite -> course}.
Course Schedule I asks whether all nodes are removed; II asks for the order.
A cycle leaves nodes with unmet prerequisites.

Alien Dictionary first builds the graph. Include every observed character, even if it has no edge.
Compare adjacent words. Only the first differing characters establish an edge.
Reject a longer word before its own prefix, such as \cd{"abc"} before \cd{"ab"}.
Use adjacency sets so duplicate evidence does not increase indegree twice. Then apply Kahn's algorithm with dictionary keys.

\subsection{Union-find: are the endpoints already connected?}
Use union-find when edges arrive and component membership is the needed information.
Path compression shortens future root searches. Attach the smaller tree to the larger one.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-43}{}
\begin{pyex}
class DSU:
    def __init__(self, n):
        self.parent, self.size = list(range(n)), [1] * n
    def find(self, x):
        while x != self.parent[x]:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True
dsu = DSU(3)
dsu.union(0, 1), dsu.union(1, 2), dsu.union(0, 2) # -> (True, True, False)
\end{pyex}
\hypertarget{example-end-43}{}
\end{minipage}\par
For Redundant Connection, scan edges in input order; a failed union identifies the extra cycle edge.
For Connected Components, start at \cd{n} and subtract one per successful union, or use a simpler flood fill.
For Graph Valid Tree, require exactly \cd{n - 1} edges and connectivity. A single flood from node 0 checks the latter.
\cost{Topological sort takes \(O(V+E)\). Union-find operations take amortized \(O(\alpha(V))\), effectively constant at these sizes.}
\transfer{Use directed dependencies for ordering, undirected components for connectivity.
A visited directed node does not by itself prove a cycle; DFS needs a separate active-path state, or use Kahn's readiness count.}

\section{Weighted paths and using every edge}\label{sec:weighted}
\subsection{Dijkstra: finish the cheapest reachable state}
BFS cannot finalize unequal-cost paths by queue order.
With nonnegative edges, the smallest queued distance cannot improve after it is popped with its current best value.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-44}{}
\begin{pyex}
from heapq import heappop, heappush
def dijkstra(adj, start):
    distance = [float("inf")] * len(adj)
    distance[start] = 0
    heap = [(0, start)]
    while heap:
        cost, u = heappop(heap)
        if cost != distance[u]:
            continue                 # obsolete entry
        for v, weight in adj[u]:
            candidate = cost + weight
            if candidate < distance[v]:
                distance[v] = candidate
                heappush(heap, (candidate, v))
    return distance
dijkstra([[(1, 5), (2, 1)], [], [(1, 1)]], 0) # -> [0, 2, 1]
\end{pyex}
\hypertarget{example-end-44}{}
\end{minipage}\par
Network Delay returns the largest shortest distance, or \(-1\) if any node is unreachable.
Swim in Rising Water changes the path cost: extend with \cd{max(cost, neighbor_height)} instead of addition.
Start at the first cell's height. Pop the destination to obtain the minimum required water level.
The key property remains: extending a path cannot reduce its cost.

\subsection{A move budget needs a layer}
Cheapest Flights Within K Stops allows at most \cd{k + 1} edges.
Use one relaxation round per allowed edge. Read old distances and write to a copy.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-45}{}
\begin{pyex}
def cheapest(n, flights, start, end, k):
    distance = [float("inf")] * n
    distance[start] = 0
    for _ in range(k + 1):
        new = distance.copy()
        for u, v, price in flights:
            new[v] = min(new[v], distance[u] + price)
        distance = new
    return -1 if distance[end] == float("inf") else distance[end]
cheapest(3, [(0, 1, 1), (1, 2, 1), (0, 2, 9)], 0, 2, 0) # -> 9
\end{pyex}
\hypertarget{example-end-45}{}
\end{minipage}\par
In-place writes would allow a later edge in the same round to use an extra flight.

\subsection{Connect all points: cheapest edge into a growing tree}
Prim's algorithm keeps each outside point's cheapest connection to the current tree.
Choose the cheapest one, then update the others. For this dense complete graph, a simple scan avoids a huge edge list.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-46}{}
\begin{pyex}
def connect_points(points):
    n = len(points)
    best, used = [float("inf")] * n, [False] * n
    best[0], total = 0, 0
    for _ in range(n):
        u = min((i for i in range(n) if not used[i]), key=lambda i: best[i])
        total += best[u]
        used[u] = True
        x, y = points[u]
        for v, (a, b) in enumerate(points):
            if not used[v]:
                best[v] = min(best[v], abs(x - a) + abs(y - b))
    return total
connect_points([[0, 0], [2, 2], [3, 0]]) # -> 6
\end{pyex}
\hypertarget{example-end-46}{}
\end{minipage}\par
The cheapest edge crossing from the tree to the outside can belong to a minimum spanning tree.
Prim stores edge cost, while Dijkstra stores full path cost. They answer different questions.

\subsection{Itinerary: finish dead ends last}
Reconstruct Itinerary must consume every ticket exactly once, including duplicate tickets.
Use an Euler trail. Take smallest destinations first, but append airports only when no outgoing ticket remains.
Reverse that completion order.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-47}{}
\begin{pyex}
from collections import defaultdict
def itinerary(tickets):
    adj = defaultdict(list)
    for src, dst in sorted(tickets, reverse=True):
        adj[src].append(dst)
    stack, finished = ["JFK"], []
    while stack:
        if adj[stack[-1]]:
            stack.append(adj[stack[-1]].pop())
        else:
            finished.append(stack.pop())
    return finished[::-1]
itinerary([("JFK", "KUL"), ("JFK", "NRT"), ("NRT", "JFK")])
# -> ['JFK', 'NRT', 'JFK', 'KUL']
\end{pyex}
\hypertarget{example-end-47}{}
\end{minipage}\par
The statement guarantees a valid itinerary. \cd{KUL} is selected first but has no exit, so it belongs at the end.
This explains why simply recording greedy forward choices fails.
\cost{Dijkstra is \(O((V+E)\log V)\) on these simple graphs; limited relaxation is \(O((k+1)E)\).
Dense Prim is \(O(n^2)\) time and \(O(n)\) space. Itinerary sorting is \(O(E\log E)\).}
\transfer{Define what a path costs and whether extending it can lower that cost.
If remaining moves change the future, add a layer. If every edge must be used, reason about edges rather than marking each vertex once.}

\section{DP: keep only the facts that change the future}\label{sec:dp}
DP merges repeated subproblems. Define a state in one sentence, list its legal choices, and combine their answers.
Use \cd{min} for minimum cost, \cd{max} for maximum value, \cd{or} for existence, and addition for counts of distinct choices.
Choose the base case from that meaning.

\subsection{Take or skip; extend or restart}
For House Robber, the best result for a prefix either skips its last house or takes it and skips its neighbor.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-48}{}
\begin{pyex}
def rob(nums):
    best = [0, 0]
    for money in nums:
        best.append(max(best[-1], best[-2] + money))
    return best[-1]
rob([2, 7, 9, 3, 1])                 # -> 12
\end{pyex}
\hypertarget{example-end-48}{}
\end{minipage}\par
For House Robber II, handle one house separately. Otherwise return the larger of \cd{rob(nums[1:])} and \cd{rob(nums[:-1])}.
A valid circular plan must exclude at least one endpoint.

For Maximum Subarray, define \cd{ending} as the best nonempty subarray ending here.
Extend the previous subarray or start a new one. Keep a separate best over all endpoints.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-49}{}
\begin{pyex}
def max_subarray(nums):
    ending = best = nums[0]
    for x in nums[1:]:
        ending = max(x, ending + x)
        best = max(best, ending)
    return best
max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]) # -> 6
max_subarray([-3, -1])                # -> -1
\end{pyex}
\hypertarget{example-end-49}{}
\end{minipage}\par
For Maximum Product Subarray, retain both extremes. A negative value can turn the smallest old product into the largest new one.

For the stock row, \cd{free[i]} is the best future profit from day \cd{i} with no share; \cd{hold[i]} is the best future profit with a share already held.

\subsection{Subsequence: an endpoint state}
A subsequence preserves order but can skip positions. For LIS, define \cd{length[i]} as its best length ending at index \cd{i}.
Try each earlier smaller value as the previous endpoint.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-51}{}
\begin{pyex}
def lis(nums):
    length = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                length[i] = max(length[i], length[j] + 1)
    return max(length, default=0)
lis([10, 9, 2, 5, 3, 7, 101, 18])   # -> 4
\end{pyex}
\hypertarget{example-end-51}{}
\end{minipage}\par
This \(O(n^2)\) form fits the base limit of 2500. The follow-up asks for \(O(n\log n)\).
For that, keep the smallest possible tail for each length. A smaller tail gives every future value at least as many ways to extend.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-52}{}
\begin{pyex}
from bisect import bisect_left
def lis_fast(nums):
    tails = []
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
lis_fast([2, 2, 2])                   # -> 1
lis_fast([3, 5, 6, 2, 4])            # -> 3
\end{pyex}
\hypertarget{example-end-52}{}
\end{minipage}\par
The tails list gives the length; its final contents need not be an actual subsequence.
\transfer{Ask whether two histories with the same proposed state always have the same available futures.
If not, add the missing fact. If yes, keep only the best result or the count for that state.
Use a full table first; compress it only after its dependencies are clear.}

\section{DP on totals: distinguish reuse and order}\label{sec:totals}
Coin Change asks for minimum count. For each total, try its last coin.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-53}{}
\begin{pyex}
def fewest_coins(coins, amount):
    dp = [0] + [float("inf")] * amount
    for total in range(1, amount + 1):
        for coin in coins:
            if coin <= total:
                dp[total] = min(dp[total], 1 + dp[total - coin])
    return -1 if dp[amount] == float("inf") else dp[amount]
fewest_coins([1, 3, 4], 6)           # -> 2
fewest_coins([2], 3)                 # -> -1
\end{pyex}
\hypertarget{example-end-53}{}
\end{minipage}\par
Greedily taking the largest coin gives \cd{4+1+1} on the first example; DP finds \cd{3+3}.
For counts, the empty total has one construction. Loop order determines which constructions are distinct.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-54}{}
\begin{pyex}
def coin_combinations(coins, amount):  # Coin Change II: order ignored
    ways = [1] + [0] * amount
    for coin in coins:
        for total in range(coin, amount + 1):
            ways[total] += ways[total - coin]
    return ways[amount]
def ordered_sums(nums, target):       # Combination Sum IV: order matters
    ways = [1] + [0] * target
    for total in range(1, target + 1):
        for x in nums:
            if x <= total:
                ways[total] += ways[total - x]
    return ways[target]
coin_combinations([1, 2, 3], 4)      # -> 4
ordered_sums([1, 2, 3], 4)           # -> 7
\end{pyex}
\hypertarget{example-end-54}{}
\end{minipage}\par
Coin-first counts each multiset once: when processing coin \cd{c}, all counted choices use only coin types processed so far.
Total-first distinguishes the last element, so \cd{1+3} and \cd{3+1} are different sequences.
These recurrences require positive denominations. With zero or negative values and unrestricted reuse, counts can be infinite.

\subsection{Use each item once}
For Equal Subset Partition, an even total is necessary. Ask whether half the total is reachable.
Build new sums from an unchanged old set so that each item is used once.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-55}{}
\begin{pyex}
def equal_partition(nums):
    total = sum(nums)
    if total % 2:
        return False
    target, reachable = total // 2, {0}
    for x in nums:
        reachable |= {s + x for s in reachable if s + x <= target}
    return target in reachable
equal_partition([1, 5, 11, 5])       # -> True
equal_partition([1, 2, 5])           # -> False
\end{pyex}
\hypertarget{example-end-55}{}
\end{minipage}\par
The right-hand set is built completely before the union changes \cd{reachable}.
For a 1-D Boolean table, scan totals downward to prevent reuse of the current item.
For unlimited reuse, scan upward so the current item can extend a total it already helped form.

Target Sum makes a sign choice for each index. Two paths with the same index and sum have the same remaining choices.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-56}{}
\begin{pyex}
from functools import cache
def target_ways(nums, target):
    @cache
    def ways(i, total):
        if i == len(nums):
            return int(total == target)
        return ways(i + 1, total + nums[i]) + ways(i + 1, total - nums[i])
    return ways(0, 0)
target_ways([1, 1, 1, 1, 1], 3)      # -> 5
target_ways([0, 0], 0)               # -> 4
\end{pyex}
\hypertarget{example-end-56}{}
\end{minipage}\par
Zeros still have two sign choices. Do not deduplicate paths when the output counts assignments.
\cost{Total-based tables usually take \(O(nT)\) time, where \(T\) is the tracked total range.}
\transfer{Before writing loops, answer three questions: can an item repeat, does order matter, and do you need existence, a count, or an optimum?
Those answers determine the state, update order, and combining operation.}

\section{DP on two sequences, grids, and intervals}\label{sec:sequence}
Two indexes often mean ``how much of each input has been consumed?''.
Use a prefix convention consistently. The extra row and column describe empty prefixes.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-57}{}
\begin{pyex}
def lcs(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = 1 + dp[i - 1][j - 1]
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]
lcs("abcde", "ace")                  # -> 3
\end{pyex}
\hypertarget{example-end-57}{}
\end{minipage}\par

\begin{longtable}{@{}L{4.2cm}L{11.8cm}@{}}
\toprule Problem and state & Legal transition \\ \midrule\endhead
Edit Distance: transform \cd{a[:i]} into \cd{b[:j]} & If final characters match, take the diagonal. Otherwise take 1 plus the minimum of up (delete), left (insert), and diagonal (replace). Initialize \cd{dp[i][0]=i}, \cd{dp[0][j]=j}.\\
Distinct Subsequences: form \cd{t[:j]} from \cd{s[:i]} & Always add \cd{dp[i-1][j]} to skip the last source character. If it matches, also add \cd{dp[i-1][j-1]} to use it. Every \cd{dp[i][0]=1}; \cd{dp[0][j]=0} for positive \cd{j}.\\
Interleaving: form \cd{s3[:i+j]} from both prefixes & Reject unequal total length first. Take from the first string if its last character matches and \cd{dp[i-1][j]} is true; similarly from the second via \cd{dp[i][j-1]}. Start \cd{dp[0][0]=True}.\\
Unique Paths: paths to cell \cd{(r,c)} & Add from above and left. First row and first column are 1. Answer is the bottom-right cell.\\
Increasing grid path: best path starting at \cd{(r,c)} & Sort cells by height, descending. Store 1 plus the largest answer among strictly higher neighbors, or 1 if none. Larger neighbors are already finished. Return the largest stored answer.\\
\bottomrule
\end{longtable}
Examples: \cd{"horse" -> "ros"} needs 3 edits.
There are 3 ways to select \cd{"rabbit"} from \cd{"rabbbit"}.
\cd{"ab"} and \cd{"cd"} can interleave as \cd{"acbd"}.
A 3-by-2 right/down grid has 3 paths.
Grid \cd{[[1,2],[4,3]]} has a strictly increasing path of length 4.

\subsection{Palindromes: expand from their centers}
An odd palindrome has one center; an even palindrome has a gap center.
Expand while opposite characters match. Each successful expansion is one palindrome.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-58}{}
\begin{pyex}
def palindrome_summary(s):
    count, start, size = 0, 0, 0
    for i in range(len(s)):
        for left, right in [(i, i), (i, i + 1)]:
            while left >= 0 and right < len(s) and s[left] == s[right]:
                count += 1
                if right - left + 1 > size:
                    start, size = left, right - left + 1
                left -= 1
                right += 1
    return count, s[start:start + size]
palindrome_summary("aaa")            # -> (6, 'aaa')
palindrome_summary("cbbd")           # -> (5, 'bb')
\end{pyex}
\hypertarget{example-end-58}{}
\end{minipage}\par
Use the count for Palindromic Substrings, or the longest range for Longest Palindromic Substring.
Save ranges during the scan; avoid copying a growing string at each expansion.

\subsection{Regex: branch on a pattern unit}
Here a dot matches one character; a star repeats its preceding unit zero or more times.
This is a whole-string match, not substring search.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-59}{}
\begin{pyex}
from functools import cache
def regex_match(s, pattern):
    @cache
    def match(i, j):
        if j == len(pattern):
            return i == len(s)
        first = i < len(s) and pattern[j] in (s[i], ".")
        if j + 1 < len(pattern) and pattern[j + 1] == "*":
            return match(i, j + 2) or (first and match(i + 1, j))
        return first and match(i + 1, j + 1)
    return match(0, 0)
regex_match("aab", "c*a*b")          # -> True
regex_match("ab", ".*c")            # -> False
\end{pyex}
\hypertarget{example-end-59}{}
\end{minipage}\par
At a star, skip the whole two-character unit, or consume one matching input character and keep the same unit.
These are exhaustive choices. The cache bounds the work by pairs of positions.

\subsection{Burst Balloons: choose the last action}
Choosing the first balloon changes the neighbors of later choices.
Choosing the last balloon in an interval fixes its two neighbors: the interval's outside walls.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-60}{}
\begin{pyex}
def burst(nums):
    a = [1] + nums + [1]
    dp = [[0] * len(a) for _ in a]
    for width in range(2, len(a)):
        for left in range(len(a) - width):
            right = left + width
            for last in range(left + 1, right):
                score = dp[left][last] + dp[last][right]
                score += a[left] * a[last] * a[right]
                dp[left][right] = max(dp[left][right], score)
    return dp[0][-1]
burst([3, 1, 5, 8])                  # -> 167
\end{pyex}
\hypertarget{example-end-60}{}
\end{minipage}\par
\cd{dp[left][right]} covers the open interval between two unburst walls.
Fill narrower intervals first so both sides of \cd{last} are available.
\cost{Two-sequence tables take \(O(mn)\) time and space. Center expansion is \(O(n^2)\) time and \(O(1)\) extra space.
Sorted grid DP is \(O(RC\log(RC))\). Burst Balloons is \(O(n^3)\) time and \(O(n^2)\) space.}
\transfer{Define the boundary of a solved subproblem. If the first action leaves unstable boundaries, try fixing the last action.
If two inputs are consumed independently, test two position indexes. Do not copy a recurrence until its state meaning matches.}

\section{Greedy: prove that alternatives can be discarded}\label{sec:greedy}
A locally attractive choice is not enough. Show that it preserves a possible optimum or that every discarded choice must fail.
Often the proof gives a small running summary.

\subsection{Reachability and a failed prefix}
Jump Game keeps the farthest reachable index. Every earlier index in that prefix is reachable too.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-61}{}
\begin{pyex}
def can_jump(nums):
    farthest = 0
    for i, reach in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + reach)
    return True
can_jump([2, 3, 1, 1, 4])            # -> True
can_jump([3, 2, 1, 0, 4])            # -> False
\end{pyex}
\hypertarget{example-end-61}{}
\end{minipage}\par
For Jump Game II, view the reachable indices as BFS layers.
Start \cd{left=right=jumps=0}. While \cd{right < n-1}, compute the largest \cd{i+nums[i]} over \cd{left..right}.
Set the next layer to \cd{[right+1, farthest]}, then increase jumps.
The input guarantees reachability. For \cd{[2,3,1,1,4]}, two layers reach the end.

For Gas Station, total gas must cover total cost. Scan with a candidate start and a running tank.
If the tank becomes negative at \cd{i}, restart at \cd{i+1} and reset the tank.
Every intermediate prefix from the old candidate was nonnegative; a later start inside that failed segment has no more fuel at \cd{i}.
Thus the whole segment can be discarded. For \cd{gas=[1,2,3,4,5]}, \cd{cost=[3,4,5,1,2]}, return 3.

\subsection{Keep only the necessary summary}
\begin{longtable}{@{}L{4.5cm}L{11.5cm}@{}}
\toprule Problem & Summary and reason \\ \midrule\endhead
Buy/Sell Stock & Treat today as the sell day. Compare its price with the minimum earlier price. Update the minimum and best profit; start best at zero.\\
Hand of Straights & Count cards and scan sorted values. The smallest unused card must start a group. Consume one copy of each of the next \cd{groupSize} consecutive values; fail if any is missing. Reject a nondivisible total first.\\
Merge Triplets & Discard triplets exceeding the target in any coordinate. Merge all others by coordinate-wise maximum. They can only help; compare the final triple with the target.\\

\end{longtable}
Examples: stock prices \cd{[7,1,5,3,6,4]} give profit 5.
Cards \cd{[1,2,3,3,4,5]} form two groups of size 3.
\cd{"abac"} partitions as lengths \cd{[3,1]}.
Triplets \cd{[2,5,3]} and \cd{[1,7,5]} merge to \cd{[2,7,5]}.

\subsection{A range can summarize all feasible states}
For Valid Parenthesis String, \cd{low} and \cd{high} are the minimum and maximum feasible numbers of unmatched openers.
A star can close, do nothing, or open, so the feasible counts remain a contiguous range.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-62}{}
\begin{pyex}
def valid_stars(s):
    low = high = 0
    for ch in s:
        if ch == "(":
            low, high = low + 1, high + 1
        elif ch == ")":
            low, high = low - 1, high - 1
        else:
            low, high = low - 1, high + 1
        if high < 0:
            return False
        low = max(low, 0)
    return low == 0
valid_stars("(*))"), valid_stars("*(") # -> (True, False)
\end{pyex}
\hypertarget{example-end-62}{}
\end{minipage}\par
If even the maximum is negative, all choices have too many closers.
Clamping the minimum removes invalid negative possibilities. At the end, zero must be feasible.
\transfer{Look for an exchange argument, a forced smallest choice, or a whole region of failed candidates.
If you cannot explain what is safely discarded, test a counterexample and keep more state with DP.}

\section{Intervals: choose a sweep order}\label{sec:interval}
Decide what equality means first. Merge Intervals treats touching closed intervals as overlapping.
Meetings can reuse a room exactly when another meeting ends.

\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-63}{}
\begin{pyex}
def merge_intervals(intervals):
    out = []
    for start, end in sorted(intervals):
        if out and start <= out[-1][1]:
            out[-1][1] = max(out[-1][1], end)
        else:
            out.append([start, end])
    return out
merge_intervals([[1, 4], [4, 5], [8, 9]]) # -> [[1, 5], [8, 9]]
\end{pyex}
\hypertarget{example-end-63}{}
\end{minipage}\par
For Insert Interval, the input is already sorted and disjoint.
Copy intervals entirely before the new interval, absorb overlaps into it, then append intervals entirely after it.
For Non-overlapping Intervals, sort by end and keep each interval whose start is at least the last kept end.
Choosing the earliest finish leaves at least as much room for future intervals. Return total minus kept.
For Meeting Rooms I, sort by start and reject any neighboring overlap.

\subsection{Count simultaneous activity}
Represent each start by \(+1\) and each end by \(-1\). Sort events and track the maximum running count.
At equal times, process ends before starts; tuple sorting does this because \(-1 < +1\).
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-64}{}
\begin{pyex}
def meeting_rooms(intervals):
    events = [(start, 1) for start, end in intervals]
    events += [(end, -1) for start, end in intervals]
    active = best = 0
    for time, change in sorted(events):
        active += change
        best = max(best, active)
    return best
meeting_rooms([(0, 30), (5, 10), (15, 20)]) # -> 2
meeting_rooms([(0, 5), (5, 9)])       # -> 1
\end{pyex}
\hypertarget{example-end-64}{}
\end{minipage}\par

\subsection{Sort queries to make candidate changes one-way}
For Minimum Interval to Include Each Query, process queries in increasing order.
Push intervals that have started, ordered by length. Pop expired intervals whenever they reach the top.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-65}{}
\begin{pyex}
from heapq import heappush, heappop
def min_intervals(intervals, queries):
    intervals = sorted(intervals)
    heap, i, answers = [], 0, {}
    for query in sorted(queries):
        while i < len(intervals) and intervals[i][0] <= query:
            start, end = intervals[i]
            heappush(heap, (end - start + 1, end))
            i += 1
        while heap and heap[0][1] < query:
            heappop(heap)
        answers[query] = heap[0][0] if heap else -1
    return [answers[q] for q in queries]
min_intervals([[1, 4], [2, 4], [3, 6], [4, 4]], [2, 3, 4, 5])
# -> [3, 3, 1, 4]
\end{pyex}
\hypertarget{example-end-65}{}
\end{minipage}\par
Expired entries may remain below the top. That is safe: only a valid top is used for an answer.
Intervals are closed here, so size is \cd{end - start + 1} and expiration is strictly \cd{end < query}.
\cost{Ordinary sweeps take \(O(n\log n)\) including sorting. Query sweep takes \(O((n+q)\log(n+q))\).}
\transfer{Choose an order in which items only enter, leave, or become final.
If answers must retain input order, save them by original index or query value and restore that order afterward.}

\section{Matrices and number operations}\label{sec:math}
\subsection{Separate reading from changing}
Set Matrix Zeroes must react only to original zeros. First record affected rows and columns, then write zeros.
For example, \cd{[[1,2],[3,0]]} becomes \cd{[[1,0],[0,0]]}.
If constant space is required, use the first row and first column as markers.
Save whether each originally contained a zero. Mark from the interior, update the interior, then update those two boundaries last.

To rotate a square matrix clockwise in place, transpose it, then reverse each row.
The coordinate mapping is \cd{(r,c) -> (c,n-1-r)}.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-66}{}
\begin{pyex}
def rotate(matrix):
    for r in range(len(matrix)):
        for c in range(r + 1, len(matrix)):
            matrix[r][c], matrix[c][r] = matrix[c][r], matrix[r][c]
    for row in matrix:
        row.reverse()
matrix = [[1, 2], [3, 4]]
rotate(matrix)
matrix                               # -> [[3, 1], [4, 2]]
\end{pyex}
\hypertarget{example-end-66}{}
\end{minipage}\par
For Spiral Matrix, track the unvisited rectangle with \cd{top, bottom, left, right}.
Read its top edge and increase top; read its right edge and decrease right.
If rows remain, read the bottom edge backward and decrease bottom.
If columns remain, read the left edge upward and increase left.
Recheck the corresponding bounds before each edge to avoid duplicating a single row or column.
\cd{[[1,2,3],[4,5,6]]} gives \cd{[1,2,3,6,5,4]}.

\subsection{Digits: process one place and carry}
For Plus One, scan right to left. Replace a 9 with 0 and continue; otherwise increment and return.
If all digits were 9, prepend 1. Thus \cd{[9,9]} becomes \cd{[1,0,0]}.
For Add Two Numbers, digits arrive least significant first.
Loop while either list or carry remains. Add available digits and carry; write \texttt{total \% 10}, carry \cd{total // 10}.
Use a dummy and tail to build the result. A final carry requires a new node.

For Multiply Strings, reverse digit lists so index \cd{i} means the \(10^i\) place.
A pair product belongs in position \cd{i+j}. Normalize carries afterward.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-67}{}
\begin{pyex}
def multiply(a, b):
    x, y = [int(ch) for ch in a[::-1]], [int(ch) for ch in b[::-1]]
    slots = [0] * (len(x) + len(y))
    for i, left in enumerate(x):
        for j, right in enumerate(y):
            slots[i + j] += left * right
    for i in range(len(slots) - 1):
        carry, slots[i] = divmod(slots[i], 10)
        slots[i + 1] += carry
    while len(slots) > 1 and slots[-1] == 0:
        slots.pop()
    return "".join(str(digit) for digit in slots[::-1])
multiply("123", "456"), multiply("0", "99") # -> ('56088', '0')
\end{pyex}
\hypertarget{example-end-67}{}
\end{minipage}\par
Reverse Integer forbids overflow beyond signed 32 bits. Work with a nonnegative magnitude and a sign-specific limit.
Check before multiplying, rather than constructing an out-of-range intermediate value.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-68}{}
\begin{pyex}
def reverse_integer(x):
    sign = -1 if x < 0 else 1
    limit = 2**31 if sign < 0 else 2**31 - 1
    x, result = abs(x), 0
    while x:
        x, digit = divmod(x, 10)
        if result > (limit - digit) // 10:
            return 0
        result = result * 10 + digit
    return sign * result
reverse_integer(-120), reverse_integer(1534236469) # -> (-21, 0)
\end{pyex}
\hypertarget{example-end-68}{}
\end{minipage}\par

\subsection{Halve repeated work; detect repeated states}
For powers, compute the half-power once, square it, and multiply by the base if the exponent is odd.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-69}{}
\begin{pyex}
def power(x, n):
    if n < 0:
        return power(1 / x, -n)
    if n == 0:
        return 1
    half = power(x, n // 2)
    return half * half * (x if n % 2 else 1)
power(2, -3), power(3, 5)            # -> (0.125, 243)
\end{pyex}
\hypertarget{example-end-69}{}
\end{minipage}\par
For Happy Number, repeatedly replace the value with the sum of its squared digits.
Stop at 1 or when the value repeats in a seen set. For 19: \(19\to82\to68\to100\to1\).
For Missing Number, subtract the actual sum from \cd{n * (n + 1) // 2}.
Python's integer arithmetic makes this direct formula safe for these bounds.

\subsection{Geometry: fix enough points to force the rest}
Detect Squares stores a \cd{Counter} of coordinate tuples, including duplicate copies.
Fix the query and a stored diagonal corner; the other two corners are then forced.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-70}{}
\begin{pyex}
from collections import Counter
def squares(points, query):
    counts = Counter(map(tuple, points))
    x, y = query
    result = 0
    for (a, b), copies in list(counts.items()):
        if a != x and abs(a - x) == abs(b - y):
            result += copies * counts[(a, y)] * counts[(x, b)]
    return result
squares([(3, 10), (11, 2), (3, 2), (11, 2)], (11, 10)) # -> 2
\end{pyex}
\hypertarget{example-end-70}{}
\end{minipage}\par
\cost{Matrix scans are \(O(RC)\); digit multiplication is \(O(mn)\); powers use \(O(\log |n|)\) recursive levels.
Square queries scan distinct stored points.}
\transfer{Use a coordinate mapping for transformations and place values for arithmetic.
If each step is deterministic, a repeated state implies a cycle.
For geometric counts, enumerate the smallest set of points that fixes the remaining coordinates.}

\section{Bits: operate on a fixed representation}\label{sec:bits}
For nonnegative integers, \cd{n & 1} reads the low bit, \cd{n >> 1} removes it, and \cd{n << 1} shifts left.
XOR cancels equal pairs: \cd{x ^ x == 0} and \cd{x ^ 0 == x}.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-71}{}
\begin{pyex}
answer = 0
for x in [4, 1, 2, 1, 2]:
    answer ^= x
answer                                # -> 4
n = 11                               # binary 1011
n & 1, n >> 1, n.bit_count()         # -> (1, 5, 3)
counts = [0] * 6
for i in range(1, 6):
    counts[i] = counts[i >> 1] + (i & 1)
counts                                # -> [0, 1, 1, 2, 1, 2]
\end{pyex}
\hypertarget{example-end-71}{}
\end{minipage}\par
For Number of 1 Bits, \cd{bit_count()} is the direct Python operation.
To implement it, add the low bit and shift until zero; alternatively \cd{n &= n-1} removes one set bit per step.
For Reverse Bits, do exactly 32 steps, including leading zeros:
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-72}{}
\begin{pyex}
def reverse_bits(n):
    result = 0
    for _ in range(32):
        result = (result << 1) | (n & 1)
        n >>= 1
    return result
reverse_bits(1)                       # -> 2147483648
\end{pyex}
\hypertarget{example-end-72}{}
\end{minipage}\par
For Sum of Two Integers, XOR adds without carry; shifted AND supplies the carry.
Python negative integers do not have a fixed width, so mask both updates to 32 bits.
\par\noindent\begin{minipage}{\linewidth}
\hypertarget{example-start-73}{}
\begin{pyex}
def bit_add(a, b):
    mask = (1 << 32) - 1
    a, b = a & mask, b & mask
    while b:
        a, b = (a ^ b) & mask, ((a & b) << 1) & mask
    return a if a < (1 << 31) else ~(a ^ mask)
bit_add(-3, 5), bit_add(-4, -7)       # -> (2, -11)
\end{pyex}
\hypertarget{example-end-73}{}
\end{minipage}\par
The final expression converts a negative two's-complement bit pattern to a Python negative integer.
In these problems, 32-bit loops have constant cost. For arbitrary widths, count the bits processed.
\transfer{Identify the bitwise property that matches the task: parity, cancellation, a digit recurrence, or carry.
Define the width and signed interpretation before using shifts on negative values.}
